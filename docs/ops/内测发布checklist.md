## 1. 自动化验收（§6.7 验收自动化；命令与 CI 一致）

### 1.1 全仓门禁（仓库根执行，workspace 统一解析）

```bash
flutter pub get          # 根目录一次覆盖全部 workspace 成员
flutter analyze          # 全部包
# 逐包测试（CI 同款循环）：每个含 test/ 的包内执行 flutter test
for d in apps/mobile packages/*; do
  if [ -d "$d/test" ]; then (cd "$d" && flutter test); fi
done
```

### 1.2 双设备一致性脚本（§6.7「双设备一致脚本」+ §3.7 验收「双设备各 100 条一致脚本 100% 通过」）

**单元/契约层（现有测试，Fake 远端，禁真实网络，§6.7）**：

```bash
# 冲突测试集四用例 + 双端各离线写 50 条 → 三轮同步收敛一致（总 100 条，§6.7）
# + 依赖序/乐观校验/schema_ver 兼容/分批续拉/分区降级/回环装配回归
cd packages/feature_sync && flutter test

# 仅跑双设备收敛与冲突用例：
cd packages/feature_sync && flutter test test/local_sync_engine_test.dart
# SyncBackend 服务端校验矩阵契约（幂等键/hlc 单调/墓碑拒绝复活/游标分批）：
cd packages/feature_sync && flutter test test/sync_backend_test.dart
# HLC 定宽编码（进位边界/回拨/跳变/同 ms 并发，§6.3）：
cd packages/core_domain && flutter test test/hlc_test.dart
```

- 远端为 `InMemorySyncBackend`（内存模拟，可注入延迟与分区）与 `LocalLoopbackBackend`（无服务端缺省装配）——**单元/契约测试禁止真实网络**；
- 注意：宿主缺 sqlite3 运行库时用例会打印 `SKIP：宿主缺 sqlite3 运行库` 并温和跳过——SKIP 视为未执行，**内测起飞前必须在 sqlite3 可用环境（或 Linux CI）拿到真实 PASS 结果（待人工复核 CI 日志）**。

**真机双设备层（§6.7 口径：两台设备各本地新增 100 条（含离线期）→ 开网双向同步 → 逐行比对一致率 100%）**：

- 前置：托管 Supabase 接入 + 设备注册 + RLS 验证——**待用户凭据**（见 §0）；
- 步骤（凭据到位后执行，结果记入 §2.4 记录表）：
  - [ ] 设备 A/B 各离线录入 100 条（含 entry_lines/food_items/todos 等同步真值表）；
  - [ ] 开网触发双向同步（启动即拉 + 前台切回 + 后台兜底，§6.2 触发时机）；
  - [ ] 双端逐行比对一致率 100%（同步真值 14 表；day_summary 等本地件**不参与比对**——投影不同步，§6.1 原则 3）；
  - [ ] `SyncStatus` 顶栏小圆点回 idle 且 pending=0。

### 1.3 帧预算与性能（§9.4 硬指标，W7-8 埋点接入后复核）

- [ ] 中端安卓（Helio G99 级）满动效丢帧 <1%；
