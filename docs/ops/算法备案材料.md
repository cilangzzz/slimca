## 1. 产品事实盘点（从设计与代码现状推导，咨询时如实陈述的事实底座）

### 1.1 AI 调用形态（§7.1 管线）

- 用户**主动输入**文本/语音转写 → 客户端组装提示词 → 云端 LLM（OpenAI 兼容协议 adapter，可插拔）→ JSON Schema 受约束解码 → 本地校验器（金额>0、kcal 区间、分类枚举等）→ 供用户确认的结构化字段（热量/金额/分类/置信度）→ 用户确认后落本地库（§7.1/§7.2）；
- 生成内容**不自动对外发布**、不生成面向第三方的对话内容；LLM 输出仅作为「初值 + 置信度标注 + 一键修正」的输入（§7.1 红线：LLM 直报热量不可信，必须经结构化+联查+确认管线）；
- AI 是增强而非依赖：超时/失败 100% 降级手填，输入页永不卡死（§7.4）；断网记录落草稿延迟解析（§2.4）；
- 免费额度每日 3 次 AI 扫描，本地计数（§3.9）。

### 1.2 供应商现状（代码证据：`packages/core_ai/lib/src/llm/openai_adapter.dart` 的 `LlmModelPreset.all`）

| 预设 | provider 标识 | baseUrl | 通道性质 | 用途 |
|---|---|---|---|---|
| gpt-4o-mini | openai | `https://api.openai.com/v1` | **境外模型通道** | 文本双解析主力（§7.5） |
| qwen-vl-plus | dashscope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 设计文档口径「国内已备案通道」（§7.5） | 拍照解析 P1（W11-12 排期） |
| glm-4v-plus | zhipu | `https://open.bigmodel.cn/api/paas/v4` | 同上 | 拍照解析 P1 |

- 供商标识随每次解析留痕：`ai_parses.provider / model`（§5.6⑭，可审计、可 A/B 对比）；
- 配置注入：`--dart-define=SLIMCA_AI_BASE / SLIMCA_AI_KEY / SLIMCA_AI_MODEL`（`apps/mobile/lib/ai/capture_parser_factory.dart`），API Key 不入仓库；
- **咨询必列问题点**：主用文本通道为境外模型（GPT-4o-mini），拍照通道为境内已备案通道——该组合对义务口径的影响（如：是否构成向境内公众提供生成内容服务、是否需调整主用通道以简化口径），必须作为 W7-8 咨询的第一优先问题；
- 拍照通道 P1 的百度菜品识别属图像识别 API（非生成式内容生成，§7.5），口径是否不同，一并咨询；
- 食物库联查为本地快表（USDA CC0 / OpenFoodFacts ODbL，§7.1），无云端个人数据依赖。

### 1.3 数据处理事实（§3.3 / §3.7 / §5.6 / §6.1）

- **raw_input 上云开关默认关**：关闭时原文即用即焚、仅落结构化结果（§3.3 P0）；
- **原图不落服务端、解析后即焚**（照片通道 P1 承诺，§1.6/§3.3/§5.6⑳）；
- 聚合/统计/余额/进度等派生数据**永不上云**（§6.1 原则 3；server/supabase 迁移中本地件 day_summary/ai_parses/sync_outbox/sync_cursors/settings 不建服务端表）；
- 全量导出（JSON/CSV）+ 一键清空（§3.7 数据主权）；
- 同步数据按用户账号 RLS 行级隔离（§6.2）；E2E 加密为 P2 规划（§6.6）。

## 4. 双供应商 fallback 说明口径（§7.4 降级第 4 级）

### 4.1 事实（代码与设计现状）

- 设计：双供应商 fallback——文本 GPT-4o-mini ↔ Qwen/GLM；拍照（P1）百度菜品识别 ↔ Vision LLM（§7.4/§7.5）；
- 代码：`LlmAdapter` 抽象可插拔、`OpenAiCompatibleConfig` 一套协议覆盖三类供应商、`LlmModelPreset.all` 三预设（§1.2）；第二供应商逻辑由上层编排（`core_ai/src/degrade/degrade_hooks.dart` 预留，llm 层不内置）；每次解析留痕 provider/model（ai_parses，§5.6⑭）；
- 超时与重试：文本 5s / 照片 12s 超时（§7.4），可重试分类线性退避（openai_adapter 行为约定）。

### 4.2 对外说明口径（咨询与提交时统一使用）

1. 供应商切换是**可用性与成本工程措施**（应对单点故障/涨价，§7.4），不改变数据处理用途、存储位置承诺与安全措施；
2. 主用/备用供应商**如实列明**（含通道性质：境外通道/境内已备案通道），不隐瞒、不混同；
3. 切换触发条件（超时/失败/限流）与降级行为（降级手填、草稿延迟解析）在隐私政策与用户说明中可查；
4. 供应商组合如有调整（尤其 Q2 结论导致的境内/境外主次调整），同步更新本节与 §3 框架项 6（待人工复核）。

### 4.3 与备案材料的关系

- 若结论为需备案：§4.1/§4.2 内容写入 §3 框架项 2/6；
- 若结论为无需独立备案：本节作为「技术服务整合」事实留痕归档，并与供应商资质凭证（如官方备案公示查询结果）一并存档；
- 无论何种结论：供应商变更、通道性质变更（P1 拍照上线）都触发本文件复核（行动项 #5）。
