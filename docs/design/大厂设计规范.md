## 1. 文档定位与来源清单

### 1.1 定位

本文是 Slimca 的「外部规范依据层」：从七路大厂规范中提炼可执行规则，逐章落到 Slimca 采用决策。原则：

1. **官方优先**：M3 / HIG / WCAG / HarmonyOS / 国产三件套官方站与源码为第一来源；【社区】来源只作参考与佐证，不单独构成硬约束。
2. **数值可核验**：官方 token 文件与 SDK 源码逐值复核。本次核查中 1 项修正（§5 label prominent 变体档位）；修正值以核查结论为准。
3. **已定值只引用**：Slimca 已定稿数值（动效五档时长、双弹簧、间距 8 档、行高、触碰目标、状态层等）只引用 `.claude/docs/ui_kit/data-model.md` 与 `docs/design/UI-规范与重设计.md`，不重复展开。
4. **拍板项显式标注**：无外部规范出处、属产品/用户拍板的设计决策，逐条标注「拍板」，不冒充规范引用。
5. **未验证项诚实声明**：官网摘录未源码复核、官方仅配图无数值的项，在 §15 速查表标「未验证」。

## 3. 设计原则（大厂提炼 → Slimca 映射）

| # | 原则 | 内容 | 来源 | Slimca 映射 |
|---|---|---|---|---|
| P1 | 系统状态可见 | 通过适当及时的反馈告知用户正在发生什么；有后果的操作不得无提示执行 | 【NNg】启发式 #1 | 同步状态、AI 解析进度可见；AI 等待骨架 ≤100ms 在场；LocalLoopback 后端状态如实呈现（describeSyncBackend） |
| P2 | 贴近真实世界 | 用用户熟悉的词语而非内部行话；遵循真实世界惯例与自然映射 | 【NNg】启发式 #2 | 「热量/花费」双账用语；金额 ¥、热量 kcal 单位直书；AI 结果用饮食/记账词汇不用模型术语 |
| P3 | 用户控制 | 提供清晰标注、可发现的「紧急出口」；支持撤销 | 【NNg】启发式 #3 | 常规删除走 snackbar undo；confirmed 后金额不可变（改账只能 supersede 新增 correction 行，历史可回溯）——CLAUDE.md 坑点 8 |

### 4.2 Tonal palette 与动态取色

- 六组 tonal palette：primary / secondary / tertiary / error / neutral / neutral-variant，每组为「仅 tone 变化（0-100），hue/chroma 不变」的完整色阶（0=黑、100=白，含 4/6/10/12/17/20/22/24/30/40/50/60/70/80/87/90/92/94/95/96/98/99 等阶）。【M3】`_md-ref-palette.scss`（confirmed）
- tone 是 HCT 色彩空间（hue/chroma/tone，基于 CAM16 × L*）的感知亮度轴。【M3】material-color-utilities（confirmed）
- 动态取色流水线：源图像 → 量化为 N 个代表色（推荐 Celebi = Wu + WSMeans）→ score 排序适配色 → scheme 生成；动态方案随暗色模式/样式/对比度偏好自动调整；另有 blend（HCT 插值）、dislike、temperature 组件。【M3】material-color-utilities
- Flutter 集成：Android S+ 取壁纸色；`DynamicColorBuilder` 同时提供明暗两套动态 ColorScheme；内容取色 `ColorScheme.fromImageProvider`；品牌色入动态方案前用 `harmonizeWith` 向 primary 的 hue 做有界偏移。【M3】pub.dev dynamic_color
- 对比度工具：contrast 组件负责测量对比度与获取满足目标的替代色，与动态方案对比度档位配合。【M3】material-color-utilities

### 4.3 明暗模式

- 语义色/动态色自适应亮暗；自定义颜色需提供亮暗两档；禁止硬编码颜色；不提供 app 内独立外观开关。【HIG】dark-mode（**拍板偏离注记**：末句 Slimca 例外不执行——主题包/编辑器/手动深浅色 W16 已定稿交付，见 §4 采用决策 6；其余 dark-mode 规则照常执行）
- iOS 暗色用 base（更暗、后退）与 elevated（更亮、前进）两组背景表达层深，弹层/浮窗自动切 elevated。【HIG】dark-mode
- 暗色对比度：前景/背景 ≥4.5:1 最低，自定义色力争 7:1（尤其小字）。【HIG】dark-mode
- Arco 暗色模式：暗色背景阶梯 bg-1…bg-5 = #17171A / #232324 / #2A2A2B / #313132 / #373739（页面→卡片→弹层逐级提亮，与 HIG base/elevated 分组同构）。【Arco】design/tokens（⚠ 官网摘录未逐值复核）

> **Slimca 采用决策（§4）**
> 1. 双主色锚定不变：健康绿 hue150=热量（kcalIn/kcalOut/net）、暖橘 hue62=金额（moneyIn/moneyOut），色相在主题包/编辑器/动态色映射三处锁定；kcal/money/success/warn/danger 一律不映射平台动态色（已定稿，data-model.md §1/§6）。
> 2. surface 五档收敛为三档：surface / surfaceMuted / surfaceCard（N98/N94/N100 浅、N6/N12/N16 深，已定稿）；新组件若需更浮层级，先论证再增档。
> 3. AA 护栏以 `enforceSlimcaAa` 装配出口为准（10 关键对，阈值 4.5 + onPrimary×primary 3.0）；warn/success 是图形语义，按 3:1 校验不进 4.5 护栏（UI-规范 §1.6）。

### 6.1 窗口大小类别

| 类别 | 宽度档 | 高度档 | 覆盖率 |
|---|---|---|---|
| 紧凑 compact | <600dp（99.96% 竖屏手机） | <480dp | — |

- 宽度类与高度类独立判定；宽度类优先（垂直滚动普遍），横屏手机等场景才需高度类；窗口大小类别随旋转/多窗口/折叠动态变化，界面应相应调整。【M3】developer.android.google.cn 窗口大小类别页

- HIG 尺寸类（size class）：宽度与高度各分 compact / regular 两档（官方无公开数值断点，UIKit 语义档），随旋转/分屏/多窗口动态切换。【HIG】layout——Slimca Android 先行暂不启用（M3 窗口类别已覆盖 Android 口径），P2 平板/跨端再对齐。
- HIG 通栏背景（edge-to-edge）：沉浸类内容可延展至系统栏（状态栏/导航栏）之后，可交互控件必须落在 safe area 内；Android 15 起对 targetSdk 35+ 强制 edge-to-edge。【HIG】layout + Android 15 行为变更——Slimca 沿用系统默认 inset 处理，P2 再评估沉浸通栏。
- tvOS 布局页边距：官方 layout 页仅配图未给数值（**待补充**；Slimca 无 tvOS 路线，不阻塞）。
- 单位基准（全文通用脚注）：vp（virtual pixel）为密度无关像素，160dpi 屏上 1vp=1px，与 Android dp 等价（1vp≈1dp）；fp（font pixel）在 vp 基础上随系统字号设置缩放，与 sp 等价（fp≈sp）。本文 HarmonyOS 数值按 vp=dp、fp=sp 直接对照阅读。【HarmonyOS】layout-basics

### 8.2 Slimca 采用决策（拍板固定项 + 规范同构依据）

1. **固定高度模式（拍板）**：弹层/抽屉高度不随内容缩放——`captureSheetHeight` 固定高度模式，内容超高走内部滚动。同构依据：HIG detents 本就是固定高度档（large/medium），不随内容伸缩。
2. **主 CTA 钉底（拍板）**：录入弹层主操作固定钉在弹层底部，与 HIG「Done 各步均在 trailing」+「每屏 1-2 个显著按钮」同构；主 CTA 每弹层唯一。
3. **单一功能入口（拍板）**：每个功能只有一个入口点；弹层不做第二功能入口。
4. **弹簧抽屉保留**：springSnappy 220ms ζ1.0、速度继承、可拖拽反向（UI-规范 §5#6 已判合规；HIG 可取消+跟手双达标）。
5. **弹层进出场不对称**：进场 curveExpand (0.05,0.7,0.1,1.0)、出场 curveCollapse (0.3,0.0,0.8,0.15)，出场不排队、整块消失（antd motion spec 规则的 M3 官方实现，UI-规范 §2.2 已定稿）。
6. **未保存下滑关闭**：录入弹层有未保存内容时下滑关闭需二次确认（对齐 HIG action sheet 确认规则；确认卡即 Slimca 的显式确认段）。
7. **弹层圆角**：新弹层组件对齐 M3 顶圆角 28dp（extraLarge）；存量弹层随改造对齐，不做专项回改。
8. **off 档**：弹层全部转场 100ms 淡入淡出（offFadeDuration，全库纪律）。

| Flutter legacy 集 | legacy (0.4,0,0.2,1)（M2 fastOutSlowIn）、legacyAccelerate (0.4,0,1,1)、legacyDecelerate (0,0,0.2,1)、linear | M2 兼容 | 【M3】Easing-class |
| HarmonyOS 标准 | (0.40, 0.00, 0.20, 1.00)（始终在视线内物体的过渡首选）；变体 (0.20,0,0.10,1.00)、(0.33,0,0.67,1.00)；减速 (0.00,0.00,0.40,1.00) 用于入场 | 屏内过渡/入场 | 【HarmonyOS】animation-attributes |
| antd easeOutQuint | (0.23, 1, 0.32, 1) | count-up/上浮收尾 | 【AntD】seed.ts |

- **2025 M3 Expressive 运动物理**：以 spring（stiffness/damping/初始速度）替代 easing+duration；expressive（带 overshoot）与 standard（少回弹）两种 scheme；token 分 spatial（位移/旋转/尺寸，允许过冲）与 effects（颜色/透明度，禁止过冲）两类，各含 fast/default/slow 三速；旧 easing+duration 系统仍可用但不再维护；该系统在 Flutter 平台状态为 Unavailable（Compose 可用）。【M3】motion/overview/how-it-works
- spring 等价曲线表（Expressive default/fast spatial、effects 三速）已在 `UI-规范与重设计.md` §1.2 定稿，此处不重复。【HarmonyOS】弹簧参数换算：interpolatingSpring(128,12,1,0) ↔ springMotion(0.555, 0.53)；springMotion 默认 response 0.55s / dampingFraction 0.825；跟手 responsiveSpringMotion 0.15s/0.86/0.25s；弹簧曲线下 duration 参数不生效。【HarmonyOS】curve API
- 帧率：交互类动效以 60FPS 为基准（1 帧 = 16.67ms@60fps），要求帧率稳定。【HarmonyOS】animation-attributes

### 9.3 Reduce Motion 与 off 档映射

系统信号接线与降级映射已在 `UI-规范与重设计.md` §2.3 定稿（HIG 五条 → Slimca 实现）：收紧 spring（reduced ×0.6）/ 动画跟手 / 不做 z 轴深度动画（reduced 换 fade）/ 位移转场改 fade（off 全部 100ms）/ 不动画 blur。外部依据：

- 【HIG】Reduce Motion：减少自动/重复动画、收紧弹簧、动画直接跟随手势、避免 z 轴层深、x/y/z 转场改 fade、避免 blur 进出。
- 【WCAG】SC 2.3.3：交互触发动效可关闭；视差滚动被点名为非必要动效。
- 【AntD】提供 `reduceMotion()/restoreMotion()` 全组件跳过动画，可跟随系统 prefers-reduced-motion（与 off 档策略同构）。

> **Slimca 采用决策（§9）**
> 1. 五档时长 + 双弹簧全部保留不改（官方刻度邻域内，UI-规范 §2.1 已判定）；新增动效时长一律取 M3 官方刻度值。
> 2. **MotionLevel=off 全库纪律（拍板）**：每条动画路径必须显式 off 分支（100ms fadeOff，Curves.linear），对应系统「减弱动态效果」（disableAnimations / reduceMotion → 强制 reduced；Android「移除动画」→ off）。
> 3. **动效 token 绑定帧预算（拍板）**：改 ui_kit tokens/transitions 必须跑 telemetry 验证帧预算；切日 ≤280ms、抽屉 ≤280ms、落库飞入 ≤450ms、骨架出现 ≤100ms（data-model.md §8）。
> 4. 禁裸时长/曲线：上层包一律从 MotionConfig 取（坑点 11、pitfalls）。
> 5. spatial/effects 判定线：位置/旋转/尺寸/圆角可过冲（springSoft），颜色/透明度禁过冲（curveEffectsStandard）。

### 13.4 Reduce Motion 与语义

- HIG Reduce Motion 五条替代做法与 Slimca off/reduced 档映射：见 `UI-规范与重设计.md` §2.3（收紧 spring / 跟手 / 去 z 轴 / fade 替代位移 / 去 blur）+ WCAG 2.3.3。【HIG】accessibility +【WCAG】
- RTL：数字字形永不镜像、内部位数顺序永不翻转；进度条/滑杆等方向性控件随 locale 翻转。【HIG】right-to-left
- 动效非唯一通道：动效不能作为传达重要信息的唯一方式，辅以 haptics 与音频。【HIG】motion
- 系统手势必须有替代路径：核心功能不能只有手势一条路径（边缘滑动返回 ≠ 省掉 Back 按钮）。【HIG】gestures

> **Slimca 采用决策（§13）**
> 1. WCAG AA 护栏已内建（buildTheme 装配出口幂等降级，10 关键对）；热量环、置信度点等图形语义按 3:1 校验而非 4.5（UI-规范 §1.6 已定稿）。
> 2. 系统减弱动效信号接线：`disableAnimations || reduceMotion` → MotionLevel.reduced；Android「移除动画」→ off。
> 3. 全部文字 sp、布局 dp；支持 200% 字号不破版（横排改竖排堆叠、行容器增高）——200% 走系统 textScaler 与 textTheme 缩放，in-app fontScale 0.85-1.3 只是叠加系数（上限低于 200% 是产品拍板，分工见 §13.3）；200% 验证点：仪表盘、设置、统计三类页面逐页走查不截断。
> 4. 每屏视觉 1-2 个显著按钮即语义层级；重要操作完成可给确认反馈（snackbar/haptic）。
> 5. 手势均有按钮替代路径；动效 off 档下信息不依赖动画传达。
