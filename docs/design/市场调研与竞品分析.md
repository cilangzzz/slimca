# 市场调研与竞品分析

> **项目**：slimca —— 日期仪表盘 +「记录一件事」AI 解析（热量 + 花费）+ 分开记账 + 健身 + 计划（待办 / 健身计划 / 存钱目标）+ 跨设备同步 + 主题自定义 + 高强度过渡动画
> **调研日期**：2026-11-16
> **调研方式**：5 路并行调研（① 国际商业产品 ② 中文市场产品 ③ 开源与自建生态 ④ 生活方式 OS 类新品 ⑤ 技术事实与基建选型）
> **文档用途**：作为设计文档（需求 9）的定位依据，回答「网上是否有类似功能」「差异在哪」「风险是什么」

---

## 1. 结论速览（TL;DR）

1. **没有任何成熟产品同时覆盖九项需求。** 五路调研交叉确认：「AI 解析一件事 → 同时得到热量 + 花费 + 统一日期仪表盘 + 记账 + 健身 + 计划（含存钱目标）」的组合，在 2026-11 时点仍是市场空白。新起开发有充分依据。
2. **每个单项都已被验证，组合无人做透。** 拍照算热量已是红海（MyFitnessPal 于 2026-03 收购 Cal AI）；AI 记账是 2025-2026 记账类标配；但「钱」与「卡路里」在任何成熟产品中都未打通。
3. **最接近的竞品共 8 个，全部缺两块以上**：平生（Vitae）、Kiomora、Discipline AI、The Life App、OptiMate、Meal & Cost Tracker（Meshi Log）、ZenTrack、明日生活——它们分别验证了方向可行性，但均为单端、早期产品或功能残缺。
4. **差异化机会集中在四点**：一条记录双产出（热量 + 金额）、日期仪表盘作为唯一首页、主题自定义 + 高强度动效作为核心体验、定价透明 + 隐私优先同步——这四点在全部竞品中均为空白。
5. **主要风险**：大厂快速跟进、AI 识别成本与精度预期、健康 + 财务数据的双重合规、同步基建动荡、九项需求范围过大导致执行失焦。

### 2.3 开源与自建生态

- **两个生态完全分叉**：热量生态（OpenNutriTracker 2919★、FoodYou 626★）与记账生态（Actual Budget 30285★、Firefly III 25259★、BeeCount 2818★）之间没有成熟的桥。
- **唯一融合尝试已夭折**：smart-diet-ledger（Flutter + Gemini，AI 识别食物→热量+花销）仅 4 commits 即停更——想法有人试过，无人做成。
- **可复用部件**：
  - 蜜蜂记账 BeeCount（Flutter，本地 SQLite + OCR 记账 + 自建 Supabase/iCloud/WebDAV/S3 同步 + 内置 MCP 接口）——但 license 为自定义非标准 OSI，商用前必须逐条审查；
  - 好享记账 journal-flutter（MIT，自然语言/语音→账目，Flutter 前端 + Java 后端全开源）——AI 记账管线可直接参考；
  - AI 食物识别共识管线：**Vision LLM 只输出「菜名 + 克数」结构化 JSON → 联查 USDA FoodData Central（CC0）/ Open Food Facts（ODbL）算热量**，而非直接信 LLM 报数（FoodShot Core 为范例）。
- **同步基建 2025-2026 大洗牌**：Triplit 被 Supabase 收购后停更、ElectricSQL 被 Databricks 收购且核心仓库 404、MongoDB Realm Device Sync 已于 2025-09 移除——三者均不可作新项目底座；PowerSync（官方 Flutter SDK + drift 集成；客户端 SDK 宽松许可，但服务端为 FSL-1.1、商用自托管需法务确认）是调研时点最稳妥的现成方案。**设计文档定稿（2026-11-16）为：自研 outbox+HLC + 托管 Supabase 起步，PowerSync 降为备选（FSL 未过法务前不引入，见设计文档 §6/§10、开放问题 #1）。**

### 4.2 逐个分析

#### ① 平生（Vitae）—— 中文市场最直接的竞品

- **是什么**：iOS 独立应用（App Store 中国区 id6763250273，个人开发者，2026 年新上架，v1.4.6 2026-08-29）。AI 记账（票据/截图→待复核账单、多币种、信用卡提醒、周月年统计）+ 拍照识别食物热量（40+ 食物库 + 图表）+ 健身（110+ 动作、组间计时、PR 追踪）+ AI 待办（语音一句话建任务）+ 资产净值 + 纪念日/倒数日（农历）+ HealthKit + 「自知复盘」（财务×饮食×健身×睡眠跨维度周/月分析）+ SwiftData 本地优先 + iCloud/CloudKit 私有库同步 + JSON 全量导出。
- **重叠**：九项需求中几乎逐条对应，是唯一同时覆盖「记账+热量+健身+待办+同步」的产品，验证了个人开发者可以做出这个组合。
- **差距**：仅 iOS 无安卓；2026 年新品、评分样本仅 3–5 条；食物库仅 40+ 条（薄荷为百万级）；未检索到存钱目标模块；无「统一日期仪表盘」入口形态（以模块页+复盘为主）；主题自定义与过渡动画未作为卖点。
- **启示**：组合方向可行且单人可维护；其短板（跨端、日期仪表盘、存钱、动效）正是本项目的差异空间。

#### ② Kiomora —— 「记一件事→AI 拆解」的同构产品

- **是什么**：iOS 独占（中国区有上架）。SuperLog：一次自然语言/语音（最长 5 分钟）/最多 3 张照片输入，AI 拆解成食物（热量/宏量）、睡眠、运动、花费、习惯、任务等多张可编辑卡片；可自定义 Home Grid 仪表盘（Life Map 连签、Daily Score 圆环、热量环、Today Board 任务）；Ask Kiomora 对话+实时语音问答自己的数据；周报/月报。
- **重叠**：全球范围内与本项目重叠度最高的产品——统一入口记录 + AI 解析出热量与花费 + 可定制仪表盘 + 任务，直接验证了产品方向可行性。
- **差距**：花费只是流水记录（无分类记账、无多账本、无收支统计报表）；无存钱目标；无健身计划模板；仅 iOS、跨端同步能力未见说明；主题自定义与动效未见宣传；独立评测稀少。
- **启示**：它验证了「AI 拆解」这半边，但没有占住「认真记账 + 计划」这半边。

#### ③ Discipline AI —— 要素覆盖最全（但纯 Web）

- **是什么**：网页版（Product Hunt 2026-03 上架）。AI Coach 每日 50 条 + 2000 万+ 食物库热量追踪 + 分类预算与**存钱目标** + 800+ 动作库与 AI 训练计划 + AI 自动生成日程 + 习惯打卡。明确宣称「用一个 AI 平台取代健身追踪、卡路里计数、预算 App 和待办清单」。
- **重叠**：需求 3/4/5 要素覆盖最全，含存钱目标。
- **差距**：纯 Web 无原生 App 动效体验；无「一条记录同时产出热量+花费」的解析；以 AI 日程为中心而非日期仪表盘；上线仅数月无规模验证；团队背景为酒店运营而非健康/金融领域。
- **启示**：定价锚点参考（早鸟 $4.95/月年付、$99 终身买断——极激进定价说明组合产品用户对价格敏感）。

#### ④ The Life App —— 统一仪表盘的同构形态

- **是什么**：Web + iPhone 同步。单一仪表盘同屏展示：净值 / 剩余预算 / 今日热量 / 体重 / 训练组数 / 餐食扫描；财务含预算、账户关联、净值、负债清偿、投资偏离；AI 助手自然语言提问；宣称无广告不卖数据。
- **重叠**：首页形态与本项目的日期仪表盘设想几乎同构。
- **差距**：花费与热量是两个平行模块，未验证「一条记录双产出」；官网混有大量无关 SEO 博文、功能宣称无第三方评测背书；无多账本、存钱目标的细化设计。
- **启示**：仪表盘同屏「钱+热量」的视觉范式可直接借鉴。

#### ⑤ OptiMate —— 「每餐热量+每餐花费」的唯一原生实现

- **是什么**：iOS/Android 极早期产品（Google Play 下载个位数级）。拍照识别热量+宏量（含手动搜索兜底）+ 每餐花费记录、每月食品预算目标与图表 + 体重/BMI、运动记录、总热量收支 + 周报/月报 + 15+ 语言、离线支持。
- **重叠**：需求 2 双解析的唯一原生实现之一，验证了「每餐记花费」的产品可行性与交互形态。
- **差距**：花费仅限「食物预算」，不是完整记账（无分类/多账本）；无存钱目标、无待办；极早期无评测；主题仅渐变级别。
- **启示**：食物月预算（每餐花费、每日支出、图表）是值得吸收的功能设计。

#### ⑥ Meal & Cost Tracker（Meshi Log）—— 核心交互的最小验证案例

- **是什么**：日本开发者的小应用（iOS id6761912060，免费，4.2MB）。一餐同时记录热量与餐费（**同一条记录双字段**）+ 拍照 AI 识别食物建议热量 + 输入食物名自动从 1000+ 食物库填热量 + 月度伙食预算。
- **重叠**：全球唯一实现「一餐=热量+餐费」双字段的产品，正是需求 2 的最小验证案例。
- **差距**：花费为手动输入、无 AI 解析金额；仅覆盖「吃」一个域；无多账本、统计弱；无跨设备同步与主题动效。
- **启示**：把「记一件事 → AI 同时算出钱和热量」做深做全，就是本产品最直接的差异化点。

#### ⑦ ZenTrack —— 免费三合一的 Android 样本

- **是什么**：Android 免费（无内购无广告、数据全本地）。三板块：效率（待办/习惯连签）+ 财务（收入/支出/储蓄+饼图）+ 健康（运动+热量追踪），每日仪表盘聚合三板块。
- **重叠**：需求 3/4/5 的免费三合一实现 + 统一每日面板雏形。
- **差距**：无 AI 食物识别与自动解析；无跨设备同步；无存钱目标、健身计划深度；无主题动效；iOS 缺失。
- **启示**：三板块每日面板的信息架构可参考；「纯本地」正是可打击的短板。

#### ⑧ 明日生活 —— 中文市场形态最接近者

- **是什么**：iOS（中国区 id6775386081）。「今天吃什么」AI 三餐建议+拍冰箱识食材、「明天怎么动」32 种运动计划+卡路里打卡、「花了多少钱」随手记账+月度概览+预算提醒、「今日计划」三大卡片、「这周过得怎样」五维评分周报告。
- **重叠**：中文市场形态最接近的竞品，覆盖需求 1/2/3/4/5 的大部分。
- **差距**：数据仅存本地、无跨设备同步（官方明确表述）；仅 1 条评分；记账无多账本/存钱目标；无 AI 单条记录双产出（热量与花费分离）。
- **启示**：「无同步」正是可打击的短板；¥9–12/月定价证明中文用户为此组合付费意愿存在。

## 5. 市场空白（Gaps）

1. **「记一件事 → AI 同时解析热量 + 金额」无成熟实现。** 唯一双字段产品 Meshi Log 金额靠手填；OptiMate 极早期且仅限食物预算；开源 smart-diet-ledger 4 commits 停更。核心交互无人占位。
2. **中文成熟市场「钱」与「卡路里」割裂。** 记账阵营（钱迹/随手记/一木/iCost）与健康阵营（薄荷/Keep/好轻/小米）互不越界，没有一家打通；蚂蚁+薄荷、MFP+Cal AI 两大收购也均未打通。
3. **「统一日期仪表盘 = 唯一首页」无人做透。** 时光序/钱迹/滴答清单只把日历当视图，没有任何产品做到「仪表盘 = 当日钱 + 热量 + 运动 + 待办的汇总首页」。
4. **记账 + 存钱目标 + 健身计划三合一缺失。** 存钱模块仅钱迹内置（365/52 周存钱法）；Discipline AI 有存钱目标但是纯 Web；组合型小产品全部没有。
5. **主题自定义 + 高强度动效在健康/热量类普遍缺失。** 主流热量类产品无一以动效为核心体验；仅 OptiMate（渐变）、卡记（多主题）、时光序（换肤）提及，且均为附属功能。动效对留存的价值已有独立证据（记账类用户平均约 3 周流失，2026 年独立开发者普遍把微动画/治愈系视觉/网格化日期视图作为留存手段）。
6. **跨平台 + 隐私优先同步组合缺位。** 组合型新品均单端（平生/Kiomora 仅 iOS）或无同步（ZenTrack/明日生活仅本地）；local-first + 端到端/iCloud 路线已被独立开发者验证（卡记 1.7MB 无账号、Lani 纯 iCloud、iCost 加密同步），但无人跨双端实现。
7. **AI 热量信任层空白。** 全行业精度自报口径混杂（标签 ±20%、营养师 ±40%、手动 ±53%、商业自报 ±15%、学界 GPT-4o 餐级约 55%），无产品把「置信度标注 + 一键修正」做成一等交互。
8. **中文食物深度覆盖与低成本解析路径未被组合产品利用。** 百度菜品识别（9000+ 菜品、¥0.30–0.70/千次、返回卡路里）便宜可用；《中国食物成分表》无开放 API；薄荷 160 万条库被蚂蚁生态锁定——组合产品可以从「中文场景优先」切入。

## 6. 机会点与差异化主张

### 6.1 机会点

组合赛道**已被验证但无强者**：巨头动作（MFP 收购 Cal AI、蚂蚁持股薄荷、Keep AI 化）证明「拍照→热量」与「AI 记账」各自是主流方向，但没有任何成熟产品把「钱 + 热量」放进同一个记录、同一个仪表盘；先行小产品（平生/Kiomora/Discipline AI/The Life App/明日生活）全部单端、无规模、缺两块以上。2026-11 时点的窗口明确：以跨平台做「日期仪表盘唯一入口 + 一条 AI 记录同时入账热量与金额 + 真实记账（分类/多账本/统计）+ 计划三件套」，动效与主题作为核心体验而非附属，定价透明与隐私优先同步作为信任卖点。

### 6.2 差异化主张（按优先级）

1. **一条记录双产出**：自然语言/语音/照片一次输入，AI 同时解析热量（宏量）与金额（分类、账本建议），落库前可编辑确认——市场上唯一近似的 Meshi Log 金额仍靠手填。
2. **日期仪表盘 = 唯一首页**：今日热量环 + 支出 + 运动 + 待办 + 计划进度一屏卡片墙（参照 RISE「日期墙」、Structured「时间轴」、Amie「动效」三个已被交叉验证的范式），一切围绕日期组织。
3. **记账是认真的**：分类、多账本、预算、周/月/年统计报表，交互对标一木记账/iCost；热量账本与真实账本共用「收入-支出-结余」心智（把卡记式隐喻升级为真实记账）。
4. **计划三件套进仪表盘**：待办、健身计划（含组间计时）、存钱目标（365/52 周存钱法）与每日记录联动。
5. **跨平台 + 隐私优先**：Flutter 单栈双端，本地优先（Drift）+ 可选云同步（设计文档定稿：托管 Supabase 起步，PowerSync/自托管/E2E 为备选与后置项，见设计文档 §6/§10），无广告、数据可全量导出。
6. **动效与主题一等公民**：Impeller + Hero + Rive 状态机构建转场体系；ThemeExtension + dynamic_color 支持深浅色与 Material You 动态取色。
7. **信任设计**：AI 热量给出置信区间 + 一键修正闭环；定价透明、无隐性续费——直接回应 Cal AI 定价混乱/被下架/数据泄露暴露的行业痛点。

### 6.3 定位一句话

> 「记一件事，钱和卡路里一起入账」——以日期仪表盘为唯一入口的跨平台生活账本，AI 拆解、真实记账、计划闭环、动效即体验。

## 7. 风险与应对

| 风险 | 说明 | 应对建议 |
|---|---|---|
| **竞品快速跟进** | MFP+Cal AI、蚂蚁+薄荷、Keep、随手记/一木都在向 AI 化叠功能，巨头一旦打通「钱+热量」即可碾压；平生/Kiomora 等小产品迭代快 | AI 解析本身不是护城河；以交互深度、修正数据资产（食物库+用户修正回流）、跨端+动效体验构筑壁垒，快速占位 |
| **AI 成本与精度** | Vision LLM 单张照片成本不可忽视（免费档行业惯例每日约 3 次扫描）；学界基准餐级热量误差约 55%（GPT-4o）、商业口径 ±15%（Cal AI 第三方 ±14.6% MAPE），混合中餐油量/份量失准更甚（同一道菜每百克可差 300–500+ kcal） | 管线用「Vision LLM→结构化 JSON→联查百度菜品/USDA/OFF」降本；LLM 直报热量不可信；把「AI 初值 + 一键修正 + 置信度标注」设计成一等交互；包装食品走条码路径 |

| **同步基建动荡** | Triplit 被 Supabase 收购后停更、ElectricSQL 被收购且仓库 404、MongoDB Realm 已移除、Isar/Hive 停更 | 选 PowerSync（自托管 FSL 许可需法务确认）或自托管 Supabase；同步协议（稳定 ID、append-only 流水、冲突策略）先于 UI 设计（**设计文档定稿**：自研 outbox+HLC+托管 Supabase 起步，PowerSync 备选；同步协议字段 W1 冻结） |
| **范围与执行** | 九项需求横跨记账+健康+计划+同步+动效，单人/小团队易做浅做散 | MVP 分期：一期「仪表盘 + AI 双解析 + 基础记账 + 本地存储 + 基础同步」；二期「计划三件套 + 主题系统 + 动效体系 + 统计报表」；三期「生态集成/端侧识别/社交」 |
| **商业化错位** | 记账用户期待买断（一木 98 元、钱迹 128 元终身），健康用户习惯订阅（薄荷 28 元/月、Keep 218 元/年）；记账类用户平均约 3 周流失 | 双轨定价（买断 + AI 能力订阅）+ 免费档每日约 3 次扫描；终身买断档被验证有市场（Lose It! $150–300）；留存靠动效与仪表盘仪式感，而非获客 |

## 8. 对设计阶段的技术建议（来自调研佐证）

> **定稿衔接（2026-11-16）**：本节为调研期建议，最终技术选型以《产品设计文档》§10 为准，两处已按评审裁定收敛：① **同步**——定稿为「自研 outbox+HLC + 托管 Supabase 起步」，PowerSync 因服务端 FSL-1.1 许可未过法务仅作备选（SyncEngine 抽象保留随时切换的余地）；② **后端**——定稿为托管 Supabase 起步，自托管 Postgres 与 CloudKit/E2E 后置 P2。下表保留调研依据供追溯。

| 主题 | 建议 | 依据 |
|---|---|---|
| 技术栈 | **Flutter + Drift（本地 SQLite）+ PowerSync（同步）+ 自托管 Postgres**（或 iOS 侧叠加 CloudKit） | Impeller 已 iOS 全量 + Android 100% 覆盖，shader jank 基本消除；Isar/Hive/Realm 三起弃坑后「维护活跃度优先」成共识；PowerSync 官方 drift 集成（drift_sqlite_async β），Free 档 2GB/月，自托管 Apache-2.0 核心（FSL-1.1 需法务确认）；MongoDB Realm/ElectricSQL/Triplit 均不可用 |
| AI 管线 | 多模态输入（拍/语音/文本）→ Vision LLM 输出结构化 JSON（菜名+克数 / 商家+金额+分类）→ 联查 **百度菜品识别**（9000+ 菜品，¥0.30–0.70/千次，个人免费 1000 次；Kcal Bank 已验证阿里云百炼路线）+ **USDA FDC**（CC0，1000 req/h）+ **Open Food Facts**（ODbL，需署名）→ 用户确认落库 | 通用 LLM 直报热量误差大（一半以上食物超 10%）；结构化 JSON + 数据库联查是开源界共识模式 |
| 精度预期管理 | 以「先拍后改」为核心交互，AI 给初值 + 置信度 + 一键修正；预期管理话术：营养标签允许 ±20%、营养师目测 ±40%、手动 ±53%、商业自报 ±15% | NIH NUTRITION 2026：四款拍照 App 全部低估热量（高脂餐每餐约 -300 kcal）；份量是最大单一误差源 |
| 主题系统 | ThemeExtension（必须实现 lerp 以支持主题过渡动画）+ 两级 token（原始值→语义槽）+ dynamic_color（Android 12+ Monet 取色，iOS 回退 seed scheme）+ reduced-motion 降级 | 官方 material-foundation 方案；iOS 无系统级取色需自建 token |
| 动效体系 | Hero 跨页共享元素 + PageRouteBuilder 自定义转场 + Rive 状态机（文件比 Lottie 小 50–80%，复杂动画更稳）；Lottie 仅用于纯播放装饰 | Rive 二进制 + C++ runtime；Lottie 纯 Dart 解析复杂矢量易掉帧（二手基准 17–30fps，方向性参考） |
| 定价 | 双轨：98–128 元买断 + AI 能力订阅；免费档每日约 3 次 AI 扫描（行业惯例） | 记账类买断化（一木 98/钱迹 128/鲨鱼 148/年）vs 健康类订阅（薄荷 28/月、Keep 218/年）；Lose It! 终身档 $150–300 验证买断市场 |
| 差异化预留 | 「AI 助手可读」（MCP server）作为预留能力 | BeeCount/edrisranjbar/lifeos 等已内置 MCP 供 LLM 查询个人数据，是 quantified-self 新趋势 |

## 9. 数据可信度说明

- 本报告基于 2026-11-16 的多轮中英文 WebSearch（约 15+ 轮）与 GitHub API 实测（star 数/license/pushed_at 为当日数据）。部分域名（apps.apple.com、kiomora.com 等）WebFetch 被网络策略拦截，个别细节**未能最终核实**：平生会员具体价格、Kiomora Plus 价格、时光序会员权益、OptiMate/DayLeveling Pro 价格。
- 本赛道大量「评测/对比」页面实为竞品自建 SEO 内容（Nutrola、NutriScan、Calzy、Calorix、kcalm、Pacali 等）；一木记账的中文报道多为 2026 年批量发布的 SEO 软文，功能面可信但评价数据需打折。

- The Life App / DayLeveling / Meshi Log / 明日生活 / OptiMate 均为上线不久的小应用，评分样本极少，随时可能改名或停运。
- 所有价格为 2026-11 检索口径，促销与渠道差异大，以应用内实时标价为准；动画 FPS 类对比数字来自第三方博客，属方向性参考，落地前需在目标机型实测。
