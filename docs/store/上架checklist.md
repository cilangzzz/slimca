## 1. Google Play：closed testing 轨道步骤

> 顺序：内部测试先行（小名单快速验证）→ 封闭测试（扩大名单）。正式轨道的进入条件以 Play Console 当期公示为准。

- [ ] **1.1 创建应用**：Play Console → 创建应用；应用名（《aso-文案.md》§2 定稿）、默认语言中文、应用/游戏声明（应用）、免费/付费声明（免费下载+应用内购买）；包名以 apps/mobile 实际 applicationId 为准（定版后不可改，**待人工复核**冻结）；
- [ ] **1.2 商店资料**：简短/完整描述（《aso-文案.md》§4/§5 定稿）；8 张手机截图（每设备类型上限 8，《截图与视频脚本.md》§1，须真机实拍）；512×512 图标、1024×500 功能图；宣传视频 = 30s 动效视频 YouTube 链接（**待账号**：YouTube 频道）；
- [ ] **1.3 隐私政策 URL**：《隐私政策草稿.md》复核定稿后部署为公开可访问 URL（托管位置**待账号**，如 GitHub Pages/自有域名）；Play Console 填入该 URL；
- [ ] **1.4 数据安全表单**：按《google-play-数据安全表单草稿.md》逐项回填（先完成其 §4 一致性核对），**待人工复核**；
- [ ] **1.5 内容分级（IARC）问卷**：如实作答（无广告、无暴力/赌博类内容；健康类内容按「热量估算+免医疗声明」口径作答，**待人工复核**）；目标受众与内容问卷：受众年龄选择与实际功能一致（本应用不针对儿童设计），**待人工复核**；
- [ ] **1.6 应用访问权限**：说明「全部本地功能无需登录即可用」；同步/AI 无需审核方特殊凭据（免费额度每日 3 次 AI 扫描可供审核实际体验，§3.9）；如审核要求提供测试账号再补录（**待账号**）；
- [ ] **1.7 构建 release AAB**：`cd apps/mobile && flutter build appbundle`；签名方案（Play App Signing / 自有 keystore）**待人工复核**；版本号 `1.0.0+1` 口径与商店后台一致（docs/ops/内测发布checklist.md §0）；
- [ ] **1.8 内部测试轨道**：上传 AAB → 内部测试（小名单邮件，验证安装/计费/同步链路）→ 打勾记录；
- [ ] **1.9 封闭测试轨道**：创建封闭测试版本 → 选择测试名单方式（邮箱列表 / Google Group / 社区，**待账号**）→ 上传 AAB 提交审核 → 审核通过与测试人员发布；
- [ ] **1.10 封闭测试规模**：**待人工复核**：若开发者账号为个人类型（新政期注册），官方普遍要求封闭测试满足「不少于 20 名测试人员、持续参与约 14 天」方可申请正式轨道——具体人数/天数以 Play Console 当期提示为准，须在排期（W9-10 → 正式发布）预留该时间窗；
- [ ] **1.11 监控与观测**：Android Vitals + 自建埋点核对（W8 已接入，§3.9）；北极星实测启动：次日留存、录入漏斗、真机帧率（§11.1 W9-10）；
- [ ] **1.12 提审材料快照归档**：当次提交的商店资料与表单截图归档（**待账号**）。

## 2. 华为应用市场 / 小米应用商店：提审要点

> 大陆商店对资质的要求与审核口径变化频繁，以下为提审要点清单；**一切以两商店官方文档与后台当期公示为准（待人工复核）**。

**共同要点：**
- [ ] **软著证书**：大陆商店常见要求软著或等效资质（docs/ops/软著申请材料清单.md——W7-8 已启动、周期常达数月，§12.1 风险 #3；**若 W9-10 证书未下，按两商店官方确认替代材料/承诺函口径——待人工复核**）；
- [ ] **App 备案（工信部口径）**：大陆应用上架普遍涉及 App 备案要求，办理流程/状态/是否为本次提审硬前置**待人工复核**（docs/ops 现有材料未覆盖，若确认需要则新增 docs/ops 行动项并回填）；
- [ ] **算法备案关联**：AI 功能说明材料与 docs/ops/算法备案材料.md §2.2 咨询结论一致（**待人工复核**；如商店要求 AI 功能资质说明，按其咨询结论口径提交）；
- [ ] **隐私政策**：公开 URL（《隐私政策草稿.md》定稿版）；应用内可直达；
- [ ] **权限最小化**：应用不得申请与功能无关权限（本应用无定位/通讯录/短信类权限）；权限说明文案如实填写；
- [ ] **三方 SDK 清单**：同步后端、AI 供应商、监控 SDK 如实列明（与《google-play-数据安全表单草稿.md》§2 一致——**待人工复核**）；
- [ ] **素材**：截图/简介复用《aso-文案.md》《截图与视频脚本.md》并按各后台规格换算（**待账号**）；截图须真机实拍、与实际功能一致（不得出现未实现功能——华为/小米审核对「宣传与实际不符」卡审，**待人工复核**口径）；
- [ ] **计费**：华为 IAP / 小米支付接入或「当前版本无应用内计费」声明——双轨 SKU 表达见 docs/ops/内测发布checklist.md §4（开放问题 #7，W8 决策，**待人工复核**）。

**华为专项**：
- [ ] 提交「隐私合规自查报告」类材料（如后台要求，**待人工复核**）；审核会实际操作应用（准备演示数据干净的内测包）；内测/众测轨道名称与规则以后台为准（**待账号**）。

**小米专项**：
- [ ] 包名与签名一致性自查；审核周期与加急渠道以后台为准（**待账号**）；应用描述与关键词字段按后台实际字段回填（《aso-文案.md》§7 行动项 4）。

## 3. iOS TestFlight：Codemagic 云 Mac 说明（本机无 Mac）

> 前提决策：iOS 是否随 v1.0（开放问题 #11，W8）与云 Mac 方案按需 vs 月费（开放问题 #3，W9）——**两项决策待人工复核后本节才可执行**。设计口径：iOS 紧随 Android（§12.2 #11 倾向）。

- [ ] **Apple Developer Program** 注册（**待账号**）+ App Store Connect 创建 App 记录（bundle id 与 Android 包名独立，**待人工复核**命名）；
- [ ] **Codemagic 流水线**：连接本仓 → macOS 实例 `flutter build ipa` → 证书与描述文件经 Codemagic 云签名托管（Apple 账号授权；证书/密钥**不落本机、不入仓库**——**待账号**配置）→ 上传 App Store Connect TestFlight；
- [ ] **本机无 Mac 的补偿路径**（§10.3/§9.6/§12.1 风险 #1）：
  - golden 基线仅在 Linux CI 生成（规避 Windows 字体渲染差异），iOS 侧不本地产 golden；
  - iOS 真机验收、iPhone 尺寸截图（App Store 截图按机型另出，**待人工复核**机型清单）均在云 Mac/云真机执行；
  - 预留 2 周缓冲与月费预算（§12.1 风险 #1）；
- [ ] **TestFlight 分发**：内部测试组（小名单，无需 Beta 审核）→ 外部测试组（需 Beta App Review：提供 AI 功能说明与 IAP 状态——**订阅必须走 IAP**（§1.6 合规前置），**待人工复核**审核材料）；
- [ ] **30s 视频复用**：App Store 预览视频规格（时长/机型）与 Play 版差异**待人工复核**（《截图与视频脚本.md》§2 备注裁剪方案）。

## 4. 内测受众与反馈渠道

**受众（§1.3 三画像）：**
- [ ] 首批规模 20-50 人：下限须满足 Play 个人账号封闭测试门槛（§1.10）+ iOS 内部组小名单；画像配比目标 A 记账人 ~60% / B 健康人 ~30% / C 计划控 ~10%；
- [ ] 招募渠道**待人工复核**（由运营拍板：熟人圈/社区/垂直论坛等，本清单不越权指定）；
- [ ] 测试人员须知：内测数据同样受《隐私政策草稿.md》约束；可随时「一键清空」；版本更新节奏每周五 build（§11.1 排期纪律）。

**反馈渠道：**
- [ ] 应用内反馈入口（设置页，自动附带版本号/平台/构建号，**待人工复核**入口实现与定版一致）；
- [ ] 反馈邮箱（**待账号**：域名邮箱）；封闭测试 Google Group / IM 群（**待人工复核**：渠道形式由运营定）；
- [ ] 崩溃自动收集（W8 已接入，§3.9）与 Android Vitals 周巡；
- [ ] 反馈闭环纪律：每周周报（北极星次日留存 / 录入漏斗 / 帧预算，§2.3）；**不达标先修动线、不加功能**；反馈分类定级后回填里程碑排期。
